## 📋 已修复的问题

### 1. ✅ CM Agent 配置错误

**问题描述**：
- Agent 连接 `localhost:7182` 而不是 `node01:7182`
- 导致 node02 和 node03 无法被 CM Server 识别

**根本原因**：
- 初始部署时 `ansible/component/setup_cloudera_manager_slave.yml` 没有配置 `server_host`
- `scripts/add_cluster_nodes.sh` 使用 `sed` 修改配置不可靠

**修复方案**：
1. 修改 Ansible playbook，添加 Agent 配置步骤
2. 创建 `scripts/fix_agent_config.sh` 彻底重写配置
3. 更新 `scripts/add_cluster_nodes.sh` 使用完全重写配置文件
4. 启动脚本自动验证和修复配置

**使用命令**：
```bash
make fix-agent
```

---

### 2. ✅ Parcel BitTorrent 分发失败

**问题描述**：
```
Failure due to stall on seeded torrent.
```

**根本原因**：
- CM 默认使用 BitTorrent (P2P) 分发 Parcel
- 在小型集群或网络受限环境中 BitTorrent 无法正常工作

**修复方案**：
1. 禁用 BitTorrent 分发，使用 HTTP 方式
2. 提供手动分发 Parcel 脚本

**使用命令**：
```bash
# 方式 1: 禁用 BitTorrent（自动）
make fix-all

# 方式 2: 手动分发 Parcel
make distribute-parcel
```

---

### 3. ✅ SSH known_hosts 警告

**问题描述**：
```
Warning: Permanently added 'nodeXX,IP' (ECDSA) to the list of known hosts.
```

**根本原因**：
- 首次 SSH 连接时需要确认主机密钥
- CM 在自动化操作时会被这些提示中断

**修复方案**：
1. 配置 `~/.ssh/config` 禁用严格主机密钥检查
2. 预先接受所有节点的 SSH 密钥

**使用命令**：
```bash
make fix-all
```

---

### 4. ✅ 启停脚本优化

**问题描述**：
- 原启停脚本不检查 Agent 配置

**修复方案**：

- 智能等待 CM Server 启动（检测端口）


## 🔍 故障排查

### 问题 1: 修复后 Agent 仍无法连接

**检查**：
```bash
# 查看配置
ssh node02 "cat /etc/cloudera-scm-agent/config.ini | grep server_host"

# 查看日志
ssh node02 "tail -30 /var/log/cloudera-scm-agent/cloudera-scm-agent.log"
```

**解决**：
```bash
# 手动修复
ssh node02 "echo 'server_host=node01' > /etc/cloudera-scm-agent/config.ini"
ssh node02 "systemctl restart cloudera-scm-agent"
```

### 问题 2: Parcel 分发超时

**检查**：
```bash
# 检查 Parcel 文件
ls -lh /var/www/html/cloudera-repos/cdh6/*/parcels/

# 检查网络
ping -c 3 node02
```

**解决**：
```bash
# 使用手动分发
make distribute-parcel
```

### 问题 3: CM Server 无法访问

**检查**：
```bash
# 检查服务
systemctl status cloudera-scm-server

# 检查端口
netstat -tlnp | grep 7180
```

**解决**：
```bash
# 重启 CM Server
systemctl restart cloudera-scm-server

# 查看日志
tail -f /var/log/cloudera-scm-server/cloudera-scm-server.log
```
