## 🎯 概述

本文档介绍 CDH 集群的启动、停止、重启和状态检查操作。

---

## ⚡ 快速使用

### 启动集群

```bash
cd /root/setup_cdh_cluster
make start
```

### 停止集群

```bash
make stop
```

### 重启集群

```bash
make restart
```

### 查看状态

```bash
make status
```

---

## 📋 启动流程

### 自动执行的步骤

`make start` 会自动执行以下操作：

#### 步骤 1/4: 验证 Agent 配置
- ✅ 检查所有节点的 Agent 配置
- ✅ 自动修复 server_host 配置错误
- ✅ 确保 Agent 指向正确的 CM Server

#### 步骤 2/4: 启动 Master 节点服务
- ✅ 启动 MySQL 数据库
- ✅ 启动 httpd Web 服务器
- ✅ 启动 CM Server

#### 步骤 3/4: 等待 CM Server 启动
- ✅ 自动等待 CM Server 完全启动
- ✅ 检测 7180 端口监听状态
- ✅ 最多等待 60 秒

#### 步骤 4/4: 启动所有节点 Agent
- ✅ 启动 node01 Agent
- ✅ 启动 node02 Agent  
- ✅ 启动 node03 Agent

## 🔧 高级操作

### 强制停止

如果正常停止失败，使用强制停止：

```bash
make force-stop
```

这会：
- 强制终止所有 Cloudera 进程
- 清理残留进程
- 重置服务状态

---

## ⚠️ 注意事项

### 启动前

1. ✅ 确保所有节点网络连通
2. ✅ 确保 SSH 免密登录正常
3. ✅ 确保有足够磁盘空间

### 启动后

1. ⏱️ CM Server 需要 30-60 秒完全启动
2. 🌐 启动完成后访问 Web 界面
3. 📊 建议运行健康检查：`make health-check-v2`

### 停止时

1. ⚠️ 停止会中断正在运行的作业
2. 💾 确保重要数据已保存
3. 🔄 停止后可以安全重启

## 💡 故障排查

### 问题 1: Agent 无法启动

**检查配置**：
```bash
ssh node02 "cat /etc/cloudera-scm-agent/config.ini | grep server_host"
```

**修复**：
```bash
make fix-agent
```

### 问题 2: CM Server 启动超时

**查看日志**：
```bash
tail -f /var/log/cloudera-scm-server/cloudera-scm-server.log
```

**可能原因**：
- MySQL 未启动
- 端口被占用
- 磁盘空间不足

### 问题 3: 部分节点 Agent 启动失败

**检查网络**：
```bash
make check-nodes
```

**检查 SSH**：
```bash
make test-ssh
```
