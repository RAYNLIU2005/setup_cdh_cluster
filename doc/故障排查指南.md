## 服务依赖问题

### 问题：Communications link failure

**错误表现：**
```
ERROR org.hibernate.engine.jdbc.spi.SqlExceptionHelper - Communications link failure
```

**根本原因：**
- CM Server 启动时 MySQL 还未就绪
- 服务启动顺序错误

**诊断步骤：**

1. **检查服务启动时间：**
   ```bash
   make diagnose
   ```

2. **查看启动顺序：**
   ```bash
   systemctl show mysqld -p ActiveEnterTimestamp
   systemctl show cloudera-scm-server -p ActiveEnterTimestamp
   ```

3. **检查 MySQL 连接：**
   ```bash
   mysql -uroot -p'Cloudera!20200801' -e "SELECT 1"
   ```

**修复方法：**

**方法 1：自动修复（推荐）**
```bash
cd /root/setup_cdh_cluster
make fix-cm-mysql
```

**方法 2：手动重启**
```bash
make restart-services
```

**方法 3：检查并修复**
```bash
# 1. 确保 MySQL 运行
systemctl status mysqld
systemctl start mysqld

# 2. 验证连接
mysql -uroot -p'Cloudera!20200801' -e "USE scm; SELECT COUNT(*) FROM ROLES;"

# 3. 重启 CM Server
systemctl restart cloudera-scm-server

# 4. 监控日志
tail -f /var/log/cloudera-scm-server/cloudera-scm-server.log
```

**预防措施：**
- 已在 Ansible playbook 中添加服务依赖检查
- 部署时会自动等待 MySQL 就绪
- 添加了启动验证机制

## MySQL 相关问题

### 问题 1：MySQL 密码未设置或错误

**错误表现：**
```
ERROR 1045 (28000): Access denied for user 'root'@'localhost'
```

**诊断：**
```bash
# 尝试连接
mysql -uroot -p'Cloudera!20200801' -e "SELECT 1"

# 检查日志
tail -n 50 /var/log/mysqld.log
```

**修复：**
```bash
make reset-mysql
```

### 问题 2：MySQL 无法启动

**诊断步骤：**
```bash
# 1. 查看状态
systemctl status mysqld

# 2. 查看错误日志
tail -n 100 /var/log/mysqld.log

# 3. 检查端口
netstat -tuln | grep 3306
```

**常见原因和解决方案：**

1. **日志文件冲突：**
   ```bash
   systemctl stop mysqld
   rm -f /var/lib/mysql/ib_logfile*
   systemctl start mysqld
   ```

2. **权限问题：**
   ```bash
   chown -R mysql:mysql /var/lib/mysql
   chmod 755 /var/lib/mysql
   ```

3. **配置文件错误：**
   ```bash
   # 检查配置
   cat /etc/my.cnf
   
   # 测试启动
   mysqld --verbose --help
   ```

### 问题 3：SCM 数据库未初始化

**错误表现：**
```
Database 'scm' doesn't exist
```

**修复：**
```bash
# 1. 确保 MySQL 运行
systemctl start mysqld

# 2. 重新初始化
/opt/cloudera/cm/schema/scm_prepare_database.sh mysql scm scm 'SuperMan2020#h'

# 3. 验证
mysql -uroot -p'Cloudera!20200801' -e "USE scm; SHOW TABLES;"
```

## CM Server 相关问题

### 问题 1：CM Server 启动失败

**诊断流程：**

1. **检查基本状态：**
   ```bash
   systemctl status cloudera-scm-server
   ```

2. **查看详细日志：**
   ```bash
   tail -f /var/log/cloudera-scm-server/cloudera-scm-server.log
   ```

3. **使用诊断工具：**
   ```bash
   make diagnose
   ```

**常见错误和解决方案：**

#### A. MySQL 连接错误
参见 [服务依赖问题](#服务依赖问题)

#### B. 端口被占用
```bash
# 检查端口
netstat -tuln | grep 7180

# 查找占用进程
lsof -i:7180

# 强制清理
make force-stop
systemctl start cloudera-scm-server
```

#### C. 内存不足
```bash
# 检查内存
free -m

# 释放缓存
sync
echo 3 > /proc/sys/vm/drop_caches

# 如果内存真的不足，停止不必要的服务
```

### 问题 2：CM Web 界面无法访问

**诊断：**
```bash
# 1. 检查服务
systemctl status cloudera-scm-server

# 2. 检查端口
curl -I http://localhost:7180

# 3. 检查防火墙
firewall-cmd --list-ports

# 4. 健康检查
make health-check
```

**解决方案：**
```bash
# 如果服务运行但无法访问
systemctl restart cloudera-scm-server

# 如果是防火墙问题
firewall-cmd --permanent --add-port=7180/tcp
firewall-cmd --reload
```

## 网络和连接问题

### 问题 1：节点间无法通信

**诊断：**
```bash
# 检查网络连通性
ping node01
ping node02
ping node03

# 检查 SSH
ssh node01 "hostname"

# 检查 hosts 文件
cat /etc/hosts
```

**修复：**
```bash
# 1. 确保 hosts 配置正确
cat >> /etc/hosts << EOF
192.168.1.101 node01
192.168.1.102 node02
192.168.1.103 node03
EOF

# 2. 配置 SSH 免密登录
make setup-ssh

# 3. 验证连接
make nodes
```

### 问题 2：Agent 无法连接 Server

**诊断：**
```bash
# 在 Agent 节点上
systemctl status cloudera-scm-agent
tail -f /var/log/cloudera-scm-agent/cloudera-scm-agent.log

# 检查配置
cat /etc/cloudera-scm-agent/config.ini | grep server_host
```

**修复：**
```bash
# 确保 config.ini 指向正确的 Server
sed -i 's/server_host=.*/server_host=node01/' /etc/cloudera-scm-agent/config.ini

# 重启 Agent
systemctl restart cloudera-scm-agent
```

## 诊断工具使用

### 工具概览

| 工具 | 命令 | 用途 | 输出 |
|-----|------|------|------|
| 健康检查 | `make health-check` | 全面检查服务状态 | 通过/失败统计 |
| 深度诊断 | `make diagnose` | 分析依赖关系和错误 | 问题数量 |
| 服务状态 | `make status` | 查看所有服务状态 | 运行状态 |
| 日志查看 | `make logs` | 查看部署日志 | 日志内容 |

### 1. 健康检查工具

**使用场景：**
- 日常巡检
- 部署后验证
- 问题初步排查

**命令：**
```bash
make health-check
```

**输出示例：**
```

  健康检查总结
========================================

通过: 12 项
失败: 0 项

[INFO] ✓ 所有检查通过！集群状态健康
```

### 2. 深度诊断工具

**使用场景：**
- 复杂问题诊断
- 服务依赖分析
- 启动顺序问题

**命令：**
```bash
make diagnose
```

**输出包含：**
- 服务运行时间
- 启动顺序分析
- 依赖关系检查
- 错误日志分析
- 系统资源状态

### 3. 修复工具

#### A. MySQL 连接修复
```bash
make fix-cm-mysql
```
**功能：**
- 检查 MySQL 状态
- 验证连接和密码
- 重启 CM Server
- 监控启动日志

#### B. 服务重启
```bash
make restart-services
```
**功能：**
- 按正确顺序停止服务
- 等待 MySQL 就绪
- 启动 CM Server
- 验证启动成功

## 最佳实践

### 1. 部署时

✅ **正确做法：**
```bash
# 完整流程
make full-deploy

# 或分步骤
make prepare-env
make deploy
make health-check
```

❌ **避免：**
- 跳过环境准备直接部署
- 部署失败后立即重试（先诊断）
- 手动启动服务（使用 make 命令）

### 2. 运维时

✅ **定期检查：**
```bash
# 每天
make health-check

# 每周
make diagnose
```

✅ **服务重启：**
```bash
# 使用脚本（推荐）
make restart-services

# 而不是
systemctl restart cloudera-scm-server  # 可能导致依赖问题
```

### 3. 故障处理流程

```
问题发现
    ↓
健康检查 (make health-check)
    ↓
深度诊断 (make diagnose)
    ↓
定位原因
    ↓
选择修复方案
    ↓
执行修复
    ↓
验证结果 (make health-check)
    ↓
记录问题和解决方案
```

## 日志位置

| 服务 | 日志路径 |
|-----|---------|
| MySQL | `/var/log/mysqld.log` |
| CM Server | `/var/log/cloudera-scm-server/cloudera-scm-server.log` |
| CM Agent | `/var/log/cloudera-scm-agent/cloudera-scm-agent.log` |
| httpd | `/var/log/httpd/error_log` |
| 部署日志 | `/var/log/cdh_deploy.log` |
| systemd | `journalctl -u <service-name>` |

**常用日志命令：**
```bash
# 实时查看
tail -f /var/log/cloudera-scm-server/cloudera-scm-server.log

# 查看错误
grep ERROR /var/log/cloudera-scm-server/cloudera-scm-server.log | tail -n 20

# 查看最近的日志
journalctl -u cloudera-scm-server -n 100 --no-pager

# 搜索特定错误
journalctl -u cloudera-scm-server | grep "Communications link failure"
```

## 紧急恢复

### 场景：集群完全无法访问

**Step 1: 检查基础服务**
```bash
systemctl status mysqld
systemctl status cloudera-scm-server
systemctl status cloudera-scm-agent
```

**Step 2: 按顺序启动**
```bash
make restart-services
```

**Step 3: 验证**
```bash
make health-check
make diagnose
```

**Step 4: 如果仍有问题**
```bash
# 查看所有错误日志
tail -n 100 /var/log/mysqld.log
tail -n 100 /var/log/cloudera-scm-server/cloudera-scm-server.log

# 根据错误选择对应修复方案
make reset-mysql        # MySQL 问题
make fix-cm-mysql       # CM 连接问题
```
